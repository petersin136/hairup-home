# hair up — 웹사이트

웹디자이너 시안(1440px 아트보드)을 픽셀 단위로 재현하는 프로젝트입니다.
Next.js 16 (App Router) · TypeScript · Tailwind CSS v4.

## 실행

```bash
npm install
npm run dev      # http://localhost:3000
npm run build
```

## 시안 재현 규칙

- 데스크톱 기준 폭은 **1440px 고정**입니다. 화면이 넓어져도 요소는 확대하지 않고
  양옆 빈 여백만 늘어납니다. 섹션 배경색만 화면 폭 100%를 채웁니다.
- 섹션마다 시안에서 컬러/사이즈/폰트/위치를 실측해 반영합니다. 임의 변경 금지.
- 모바일 대응은 데스크톱 26개 섹션을 모두 끝낸 뒤 별도로 진행합니다.

## 픽셀 diff

구현 결과를 1440px로 스크린샷 찍어 `design/refs/`의 시안 PNG와 픽셀 단위로 비교합니다.
dev 서버가 떠 있어야 합니다.

```bash
node scripts/pixel-diff.mjs            # 전체 섹션
node scripts/pixel-diff.mjs 01-hero    # 특정 섹션만
node scripts/tune.mjs                  # CSS 후보값 A/B 비교 (보정용)
node scripts/tune.mjs 카드              # 이름에 '카드' 가 든 실험만
node scripts/measure-text.mjs          # 시안 잉크 폭으로 폰트 크기/굵기/자간 역산
node scripts/fit-text.mjs              # 아직 구현 전인 글자를 시안 크롭과 직접 대조
node scripts/capture-templates.mjs     # 07 카드에 쓸 템플릿 대문 이미지 다시 찍기
PYTHONPATH=scripts python3 scripts/probe-section.py design/refs/05-key-benefits.png --blocks
python3 scripts/probe-07.py            # 843px 로 온 07 시안 계측 (면적 적분으로 서브픽셀 역산)
python3 scripts/compare-07.py 07-1     # 07 시안과 렌더의 잉크 좌표를 나란히 비교
```

결과는 `design/diff/`에 `<name>-actual.png`, `<name>-diff.png`로 떨어집니다.
`design/diff/*-actual.png`가 만들어진 뒤에는 요소별 잉크 좌표를 표로 대조할 수 있습니다.

```bash
PYTHONPATH=scripts python3 scripts/compare-ink.py        # 전부
PYTHONPATH=scripts python3 scripts/compare-ink.py 06-1   # 이름에 06-1 이 든 것만
```

`06` 은 세 장이 이어 흐르는 띠가 되어 화면 한 장이 곧 시안 한 장이 아니므로, 장 하나를

`05` 는 카드가 넷으로 늘고 거터도 좁아져 줄 전체 위치가 시안과 다릅니다. 섹션 대조에서는
카드 줄을 가려 머리글만 보고, 카드는 시안의 같은 자리에서 오려 낸 것과 한 장씩 맞춰 봅니다
(`05-card-N`). 창이 카드 한 장으로 좁아진 만큼 같은 오차가 백분율로는 크게 잡히지만,
어긋나는 픽셀 수는 세 장을 합쳐도 전과 같고 잉크 좌표는 ±1px 안입니다.
넷째 카드는 시안 밖이라 대조 대상이 없습니다.

`01` 은 헤더 메뉴와 CTA 라벨을 영문 기본으로 바꿔 글자 자체가 시안과 달라, 그 두 자리만
가리고 나머지를 봅니다. 한글이 굴러 올라온 자리가 시안 줄과 맞는지는 따로 잽니다.

```bash
node scripts/probe-header.mjs && PYTHONPATH=scripts python3 scripts/probe-header.py
```

글자 크기·굵기·자간·위치는 모든 섹션에서 잉크 바운딩 박스 기준 ±1px 안에 맞춰져 있고,
남은 오차는 Figma와 Chrome의 안티에일리어싱 차이입니다. 작은 한글이 많거나 가운데
정렬이라 글자가 소수점 좌표에 떨어지는 섹션일수록 이 값이 자연히 커져서, 허용치는
전역 하나가 아니라 섹션마다 둡니다.

### 07 시안만 843px 로 왔습니다

다른 섹션은 1440 네이티브 시안이라 스크린샷을 그대로 겹쳐 볼 수 있는데, `07` 세 장은
843 × 1024(배율 0.585)로 축소 저장돼 왔습니다. 시안을 1440 으로 늘리면 흐려져 비교가
무의미해지므로, 반대로 **스크린샷을 843 으로 줄여서** 맞춥니다.

이 때문에 좌표는 ±1px 이 한계이고, 축소하면서 글자 안티에일리어싱이 뭉개져 허용치도
다른 섹션보다 높습니다. 실제로 남은 오차의 절반가량이 하단 문구 띠이고 나머지는
헤더 글자와 카드 모서리인데, 같은 헤더가 1440 시안인 `05` 에서는 훨씬 낮게 나옵니다.
**1440 폭 원본을 받으면 좌표를 다시 재서 허용치를 다른 섹션 수준으로 낮출 수 있습니다.**

카드 안쪽은 시안이 검정 플레이스홀더라, 비교할 때만 대문 이미지를 감춰
(`[data-cover] { visibility: hidden }`) 같은 조건으로 맞춥니다.

## 아직 시안이 없거나 확정 전인 부분

`02` 섹션은 시안 확정 전이라 `SectionPlaceholder`로 1440 × 800 검정 블록만 잡아 뒀습니다.
`03_Test`의 600 × 768 검정 패널, `05`의 검정 카드 3장, `06`의 크림색 박스도 시안에
내용이 없어 단색 면으로만 두었습니다.

`05`의 세 번째 카드 문구는 시안에서 화면 오른쪽으로 잘려 있어 읽히는 데까지만
`src/content/site.ts`에 옮겼습니다. 전문을 받으면 그 항목만 채우면 됩니다.

`07`은 확정 전인 항목이 셋 있고 모두 `src/content/site.ts`의 `templateCollection`에 있습니다.

- 템플릿 이름: 시안에 적힌 것은 `01 / Studio Signature` 뿐이라 `02` `03` 은 임시 이름입니다.
- 하단 문구 띠: 시안에서 양끝이 잘려 있어 첫 문구를 `PURE DESIGN FOCUS`,
  마지막을 `EFFORTLESS BOOKING`으로 추정해 넣었습니다.
- 카드 대문 이미지: `scripts/capture-templates.mjs`가 세 데모 사이트의 첫 화면을
  1600 × 1000으로 찍어 `public/templates/`에 저장한 것입니다. 1번 템플릿
  (`maranathahomepage`)은 히어로가 검정 배경이라 카드가 거의 검게 보입니다.

## 모션

시안에 모션 스펙이 없어 아래 항목들은 동작 방식만 확정하고 수치는 최소한으로 잡았습니다.

- 헤더 메뉴 · CTA — 영문이 기본이고 가리키면 한글이 아래에서 굴러 올라옵니다(0.5초).
  두 언어를 같은 격자 칸에 겹쳐 두어 칸 폭이 둘 중 넓은 쪽으로 잡히므로 글자가 바뀌어도
  메뉴 간격이 흔들리지 않습니다. 한글이 올라온 자리는 시안 그대로이고(메뉴 잉크 y 54..70,
  CTA 라벨 y 56..72), 영문은 그 한글과 잉크 가운데가 같은 높이에 오도록 맞췄습니다.
  영문 표기(`AI MANAGER` · `TEMPLATE` · `PRICING` · `FAQ` · `CREATE MY BRAND`)는 시안에
  없어 한글 뜻에 맞춰 새로 정한 값이라 언제든 바꿀 수 있습니다.
- `05_Key Benefits` 카드 줄 — 가로 드래그·스크롤. 시안은 세 장이지만 원래 넷까지 있는
  구성이라 한 장을 더 달았고(500 + 간격 33), 줄을 넓혀 달라는 요청으로 좌우 거터를
  시안의 120 에서 80 으로 같게 좁혔습니다(가운데 정렬). 넷째 카드 문구는 아직 임시값입니다.
- `06_The Process` — 한 장씩 갈아 끼우지 않고 세 장을 옆으로 이어 붙여 오른쪽에서
  왼쪽으로 계속 흐릅니다. 한 장은 아트보드 1440 에서 좌우 여백을 60 씩 덜어낸 1320 이라
  화면 끝에 다음 장이 걸쳐 보이고, 장과 장이 붙어 있어 배경색이 바뀌는 자리가 곧
  경계입니다(안쪽 좌표는 시안 그대로). 한 장이 지나가는 데 14초, 세 장이 한 바퀴입니다.
  세 장 주기로 그림이 똑같으므로 한 바퀴에서 소리 없이 되감아 이음매가 없습니다.
  좌우로 끌어 직접 돌릴 수 있고 끄는 동안에는 흐름이 멈춥니다.
  `prefers-reduced-motion` 이면 흐르지 않고 서 있습니다(드래그는 됩니다).
- `07_Template Collection` 카드 줄 — 가운데 한 장만 800 × 500 으로 크고 좌우 이웃은
  800 × 426 으로 화면 밖까지 걸칩니다. 좌우로 드래그하거나(카드 폭의 20%만 끌면 넘어감)
  걸쳐 있는 카드를 눌러 가운데로 가져올 수 있습니다. 목록을 몇 벌 이어 붙인 유한한 줄이
  아니라 끝없이 뻗은 자리 번호 위에 카드를 놓고 가운데 좌우 3장씩만 그리므로, 몇 번을
  넘겨도 처음으로 되돌리는 순간이 없고 따라서 튀지 않습니다.
- `07` 카드 호버 — 대문 이미지가 4% 확대되면서 어두워지고 템플릿 이름과 VIEW DEMO
  버튼이 떠오릅니다. 버튼에 호버하면 테두리만 있던 것이 크림색으로 채워지고, 누르면
  해당 데모 사이트가 새 탭에서 열립니다.
  덮는 정도(90%)는 시안에서 읽어낸 값이 아닙니다. 시안 카드가 호버 상태에서도 검정
  플레이스홀더라 스크림 세기를 알 수 없고, 1번 템플릿 대문에 크고 흰 문구가 정확히
  오버레이 자리에 있어 이만큼 덮어야 겹쳐 읽히지 않습니다. 대문 이미지가 확정되면
  더 옅게 줄일 수 있습니다.
- `07` 하단 문구 띠 — 문구 목록을 세 벌 이어 붙여 42초에 한 벌만큼, 오른쪽에서 왼쪽으로
  끊김 없이 흐릅니다. `prefers-reduced-motion` 이면 멈춰 있습니다.
- `07` 만 잘라내는 기준이 1440 캔버스가 아니라 섹션(=화면 폭)입니다. 카드 줄과 문구 띠는
  시안에서 좌우가 잘려 나가는 요소라, 1440 에서 자르면 화면이 더 넓을 때 양옆 크림 여백
  안쪽에서 뚝 끊겨 보입니다. 화면 끝에서 잘리도록 두어 계속 이어지는 것처럼 보이게 했습니다.
  1440 에서는 두 방식의 결과가 같아 시안 대조값은 그대로입니다.

## 디자인 토큰

컬러·폰트·radius는 `src/app/globals.css`의 `@theme`에 모여 있습니다.
폰트 로더는 `src/lib/fonts.ts` 한 곳에만 있어서, 실제 브랜드 폰트를 받으면
그 파일만 `next/font/local`로 바꾸면 됩니다.

### 폰트 주의사항

시안은 데스크톱용 **Noto Sans CJK KR**로 작업됐습니다. 웹폰트 Noto Sans KR은
한글 글자 폭은 같지만 공백(U+0020)이 0.057em 더 넓어 어절 위치가 어긋납니다.
`.text-kr` 유틸리티가 `word-spacing: -0.057em`으로 이 차이를 보정합니다.
한글 텍스트에는 이 클래스를 함께 붙여 주세요.

영문 세리프는 **Playfair Display로 대체**한 것입니다. 시안 원본 서체는 낱글자를
캡하이트로 정규화해 비교하면 둥근 글자(`O` `D` `C`)는 Playfair와 거의 같은데
세로획 글자가 더 좁습니다(`H` 43 대 49, `I` 15 대 19, `T` 36 대 41). 27px대에서는
차이가 묻히지만 `06`의 66px에서는 드러나서, **단어 덩어리의 폭이 시안과 맞도록**
크기를 잡았습니다. 그래서 글자 높이가 시안보다 4~5px 낮습니다.
원본 서체 파일을 받으면 `src/lib/fonts.ts`만 바꾸고 각 섹션의 크기를 다시 재면 됩니다.

`06`의 `STEP N` 은 Playfair 기본 숫자가 올드스타일(높이가 낮고 `3` 이 베이스라인
아래로 내려감)이라 `font-variant-numeric: lining-nums` 를 함께 겁니다.

## Supabase

`supabase/migrations/`에 스토리지 버킷 + RLS 정책과 자산 레지스트리 스키마가 있습니다.

| 버킷 | 공개 | 용량 제한 | 용도 |
| --- | --- | --- | --- |
| `brand` | ○ | 20MB | 로고 SVG, 파비콘, OG 이미지 |
| `images` | ○ | 30MB | 섹션 사진·일러스트 |
| `videos` | ○ | 500MB | 배경/데모 영상 (mp4, webm, mov) |
| `posters` | ○ | 10MB | 영상 첫 프레임 포스터 |
| `uploads` | ✕ | 50MB | 문의 첨부 등 비공개 업로드 |

코드에서는 경로 대신 `brand.wordmark` 같은 **asset key**로 참조합니다.
`public.site_asset_urls` 뷰가 완성된 public URL까지 만들어 줍니다.

적용 순서

1. `public.app_settings`의 `storage_public_base_url`에서 `<PROJECT_REF>`를 교체
2. `supabase/migrations/` 실행
3. Storage에 파일 업로드
4. `supabase/seed/` 실행
